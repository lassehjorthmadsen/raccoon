# data/

Top-level home for datasets shared across experiments (gitignored — see
`.gitignore`; nothing here is tracked, everything is reproducible or
re-downloadable/re-fetchable from GCS).

- `wildbg/` — CC0 wildbg-training rollout labels (`make download-wildbg`).
- `bglab/` — sparse-checkout of the bglab match archive + synthesized 4-ply /
  policy caches (see `CLAUDE.md` for the synthesis commands).
- `distill/` — GNUBG self-play distillation datasets (below).

## distill/

Positions generated by GNUBG self-play (`scripts/gen_gnubg_selfplay.py`) and
labeled at 0-ply and/or 2-ply (`scripts/relabel_2ply.py`). Organized by
**label ply** first — that's the axis experiments care about (e.g. "train on
the 2-ply data") — then by **run**, since each run is a distinct set of
positions and reuses the same `shard_w<N>_<K>.npz` filenames, so runs can't be
flattened into one directory without collisions.

```
data/distill/
  0ply/
    run1/   8M positions
    run2/   8M positions
  2ply/
    run1/   8M positions   <- same positions as 0ply/run1 (matched pair)
    run2/   8M positions   <- same positions as 0ply/run2 (matched pair)
    run3/  24M positions   <- 2-ply only, no 0-ply twin kept
```

| Run | Positions | 0-ply dir | 2-ply dir | Old name (pre-reorg) |
|---|---|---|---|---|
| run1 | 8M  | `0ply/run1` | `2ply/run1` | `cache` / `cache_2ply` |
| run2 | 8M  | `0ply/run2` | `2ply/run2` | `cache_new` / `cache_new_2ply` |
| run3 | 24M | — (deleted) | `2ply/run3` | `cache_new2` / `cache_new2_2ply` |

**2-ply total: 40M positions** (`data/distill/2ply/`). **0-ply total: 16M**
(`data/distill/0ply/`) — run3's 0-ply source was generated, relabeled, and
deleted without being kept (asymmetric by design, not an oversight).

**run1 is the matched confound-free pair**: identical positions labeled at
both plies, used by exp014's held-out R² A/B (`raccoon/data/cache_split.py`,
`scripts/eval_r2.py`) to isolate the effect of teacher ply from the effect of
which positions were sampled. run2/run3 are independent samples — do not pass
them as a `--cross-cache-dir` pair; filenames only align within a run.

**Pointing at a ply directory** (e.g. `data/distill/2ply/`) recursively
gathers every run's shards (`train_distill.py`, `eval_r2.py` both use
`Path(...).rglob("shard_*.npz")`). Pointing at a single run dir
(`data/distill/2ply/run1`) gets just that run — required for cross-cache
matching and for reproducing a specific historical result.

### GCS mirror

`data/distill/` mirrors 1:1 onto `gs://raccoon-training-lhm/data/distill/`
(same relative paths). Pipelines pull a run's shards from GCS on demand if
missing locally (see `experiments/pipeline_exp011b.sh`,
`experiments/pipeline_exp014.sh`); `scripts/resume_expand.sh` pushes newly
generated shards back to GCS as each stage completes.

### Provenance

- run1: `scripts/gen_gnubg_selfplay.py` (seed unrecorded, pre-dates
  `--seed`) → `scripts/relabel_2ply.py --ply 2`.
- run2: same pipeline, a later independent generation.
- run3: `scripts/gen_gnubg_selfplay.py --positions 24000000 --seed 12345`
  (the "expand40m" job, `scripts/resume_expand.sh`) → `relabel_2ply.py --ply 2`.
